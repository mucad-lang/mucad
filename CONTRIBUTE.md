# Contribute

Thank you for your interest in contributing to µcad!

The mucad community welcomes all contributions, including bug reports, feature requests, and pull requests.

## Find a first issue

If you found a bug or have an idea, please checkout the existing issues first ([https://codeberg.org/mucad/mucad/issues]).
If you do not find your problem or solution mentioned there, feel free to create a [new issue](https://codeberg.org/mucad/mucad/issues/new).

Issues that are good for new contributors are tagged with the [`first good issue` label.](https://codeberg.org/mucad/mucad/issues?q=&type=all&sort=relevance&labels=685366&state=open&milestone=0&project=0&assignee=0&poster=0)

## Our contribution guidelines

We aim to make contributing easy, welcoming, and enjoyable. The practices below help us keep the project healthy and accessible, and we’re always open to improving them together.

* **Documentation matters.** We try to keep code and documentation clear, readable, and up to date so others can easily understand and build on the project.

* **We lean on helpful tools.** We’re big fans of clippy and use it regularly to catch issues early and keep the codebase consistent.

* **Docs are tests, too.** We write tests through documentation, embedding µcad snippets directly in Markdown so examples stay close to the behavior they describe.

If you’re unsure about any of these or have ideas for doing things differently, that’s totally okay—questions, suggestions, and PRs are always welcome.

### Contributions generated via LLMs / Machine Learning Tools (aka "AI")

While we welcome any contribution to mucad, we are very cautious with contributions generated by LLMs.
As mucad maintainers, we use these tools daily to generate suggestions and occasionally create boilerplate code.
However, as maintainers, we are responsible for ensuring that the final product works as expected and meets our desired quality standards.
Therefore, we must review every contribution carefully before merging it.

Although the technology is evolving rapidly, our rationale is therefore as follows:

* We are cautious about accepting LLM-generated contributions due to maintenance burden, project health, and copyright infringement.

* We only accept LLM contributions if they are clearly labeled as such.
  Issues and pull requests must be labeled, and contributors must state which LLM and which prompts have been used.
  Large-scale contributions that are obviously LLM-generated are generally considered AI slop and will not be accepted.

* If you use an LLM to create code because you can't make the changes yourself, you won't be able to properly judge or review the generated work.
  This will result in you shifting the work onto others.
  Such changes are unlikely to be accepted.
  Only submit changes that you fully understand and can justify.
  If you ensure, please consider to file an issue with a feature or bug description first and then we can discuss things. 

* LLM-generated bug reports are likely to be closed.

* We expect contributed code to have working tests and clear documentation.

* From an ethical perspective, LLM tools require large amounts of energy and exploit workers under inhumane conditions.
  We advise contributors to carefully consider these side effects.

* As developers, we see the benefit of using an LLM from time to time, as it saves a lot of typing.
  However, this does not release you from the burden of reviewing and understanding.
  We want encourage authors to using their own intelligence instead off relying on artificially generated code snippets.
  Please prompt as precise and specific as possible. 
  You will notice that once you have specific prompt, the solution is clear in your head and you don't need the LLM at all.

* Both humans and AI can and will make mistakes.
  However, only humans can be responsible for the contributed code, not AI.

* µcad project's goal is to build a community, not a farm of AI agents.
  Unlike AI contributions, contributions from humans help mentor potential future maintainers.

## Getting started

First, install [*Git*](https://git-scm.com/book/en/v2/Getting-Started-Installing-Git)
and [*Rust*](https://www.rust-lang.org/tools/install).

### Getting and building the source Code

Clone the source code repository:

```sh
git clone https://codeberg.org/mucad/mucad
cd mucad
```

After cloning the repository, you can build mucad using Cargo:

```sh
cargo build
```
